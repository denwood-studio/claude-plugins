# Step 1 — gathering context, and which pass this is

1. **Diff.** `git -C <WORKTREE> fetch origin --quiet` first — unfetched, the drift check `rev-list --left-right --count main...origin/main` prints a reassuring `0 0`. Diff `origin/main...HEAD`, **never the local `main` ref**, which drifts and blames already-merged work on the PR; base later `diff`, `log` and blame on it too. **`BASE: <ref>` from the spawn block replaces it** — a **stacked** PR sits on another ticket's branch, and diffing against main attributes the upstream node's commits to this one. Qualify a bare branch name yourself. If the base won't resolve after fetching, say so **loudly in the review** and fall back to `origin/main`.
2. **Load project memory via `${CLAUDE_PLUGIN_ROOT}/scripts/review-context.sh <WORKTREE> <RANGE>`**, never by reading the files whole. `RANGE` is `SCOPE-OUTPUT`'s `RANGE:` line (Step 1.4); where there is none, use `<BASE>...HEAD`. It returns the changed files, derived search terms, `MEMORY-SIZES:`, and numbered hits in `decisions.md`, `patterns.md`, `conventions.md` and `context.md` — ground in `CONTEXT:` for the current architecture as you do in the rest. Also read `.claude/memory/index.md` if present. **Never `Read` any memory file whole when `MEMORY-SIZES` shows it over 20,000 bytes** — `sed -n '<hit-30>,<hit+30>p' <WORKTREE>/.claude/memory/<file>` a window around each hit instead. **No output** (exit 126 or 127) means the script could not run: say so in the body, then continue degraded on `index.md` and your own greps.
3. **Establish the outcome** per `outcome.md` — this is Step 1.5 of the skill and it precedes Step 2. Level 1 is the tracker's get-issue call, and does not run with no tracker connected or `TICKET: none`; the PR description is never a source.
4. **Pin the SHA and read which pass this is.** Record `git -C <WORKTREE> rev-parse HEAD`: it goes in the body (shortened) and the Step 5 trailer, and you re-check it before posting. `SCOPE-OUTPUT` already decided the pass — **never re-run the script or re-derive its output by hand**. Act on what it printed:

   - **No `SCOPE:` line** (exit 127) — full pass against the PR's base (`origin/main` if undetermined); say the scope script was unavailable.
   - **`full`, no `PRIOR_REVIEW:`** (`first-pass`, `lookup-failed`, `no-bot-login`) — Steps 2–4 in full against `RANGE`; on `lookup-failed` say the lookup failed, never mistaking it for a first pass; on `no-bot-login` say no bot login is configured, so prior reviews cannot be recognised and every pass is a full one.
   - **`full` with `PRIOR_REVIEW:`** (`no-anchor`, `anchor-not-found`, `rebase`) — full pass against `RANGE`, carrying prior findings forward as open items and stating the `REASON:`. A missing anchor is your own earlier output's property, not a defect in the PR.
   - **`delta`** — `git -C <WORKTREE> diff <RANGE>` **plus the findings you left open**, nothing else. **Do not re-run Step 3 over the whole PR**; run it only on files the delta touches that no earlier pass read.
   - **`unchanged`** — confirm the prior verdict in a couple of lines.

**Fallback — an incomplete block.** Missing `WORKTREE`, `PR`, `REPO`, `BASE` or `SCOPE-OUTPUT:`: discover it first — `git worktree list`, `gh pr view --json number,baseRefName,headRepositoryOwner,headRepository`, then `fetch origin --quiet` and `${CLAUDE_PLUGIN_ROOT}/scripts/review-scope.sh <WORKTREE> <PR> <REPO>`. No PR exists yet: the script cannot run, so make it a full pass over `<BASE>...HEAD` (`origin/main` when undetermined) and say "no PR yet" in the review.
